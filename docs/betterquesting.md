# Квесты GTNH: BetterQuesting

Отдельные `betterquesting-tools.jar` и `forge-betterquesting-1.7.10` дают агенту
доступ к книге BetterQuesting на клиенте: главы, поиск, зависимости, описания,
задания, награды и синхронизированный прогресс текущего игрока.
Базовая версия API — [BetterQuesting 3.8.89-GTNH](https://github.com/GTNewHorizons/BetterQuesting/tree/3.8.89-GTNH),
использующая UUID квестов и глав. Старый BetterQuesting с числовыми ID не поддерживается.
Совместимость с конкретной сборкой GTNH требует проверки в игре.

## Установка

После `gradlew build`:

1. Оставить `build/bundle/plugins/betterquesting-tools.jar` в каталоге плагинов MCP.
2. Положить `build/bundle/client-mods/minecraft-agent-tools-betterquesting-forge-1.7.10-*.jar`
   в `mods/` клиента с BetterQuesting GTNH. Его зависимости устанавливаются вместе с модпаком;
   BetterQuesting не включён в JAR адаптера. На выделенный сервер адаптер не устанавливается.
3. Запустить клиент самостоятельно. В `config/minecraftagenttoolsbetterquesting.cfg`
   появятся `bridge.token` и `bridge.port` (по умолчанию `25580`).
4. Передать MCP-процессу `MAT_BETTERQUESTING_TOKEN` и `MAT_BETTERQUESTING_PORT`.
   Перезапустить MCP после добавления JAR провайдера.

Адаптер и MCP работают на одном компьютере, соединение — TCP loopback с токеном.
Harness, NEI, GregTech-провайдер и серверный адаптер Minecraft для этих инструментов не нужны.
Без JAR провайдера ни один `bq_*` инструмент не регистрируется.

## Инструменты

| Инструмент | Назначение и основные аргументы |
| --- | --- |
| `bq_status` | Сессия клиента, измерение, UUID прогресса, доступность локальной книги, версия API и ограничения. |
| `bq_list_lines` | Главы в порядке книги; необязательный `query` по названию/описанию. |
| `bq_get_line` | `lineId`: описание главы, квесты с состоянием и координатами на странице книги. |
| `bq_search_quests` | Необязательные `query`, `lineId`, `state`, `visibility`: поиск и выбор следующего квеста. |
| `bq_get_quest` | `questId`: описание, статус, правила открытия/заданий, повторяемость, главы, ID заданий/наград и все сериализуемые свойства. |
| `bq_get_task` | `questId`, `taskId`: тип, выполнение, настройки и прогресс задания, требования к предметам. |
| `bq_get_reward` | `questId`, `rewardId`: тип и настройки награды, предметы, варианты выбора, команды как данные. |
| `bq_get_relations` | `questId`, `direction`: непосредственные `prerequisites` или `dependents` с состояниями и типами связей. |

Во всех вызовах после `bq_status` обязательны его `session` и `dimension`.
Это отдельная сессия, её нельзя брать из Minecraft/NEI/GregTech/Schematica.
Смена мира, измерения, объекта игрока или questing UUID делает старые запросы недействительными,
в том числе уже стоящие в очереди. UUID берётся через BetterQuesting, что важно для offline mode.

Поиск — регистронезависимое буквальное вхождение, а не регулярное выражение.
Он учитывает локализованные названия/описания, типы заданий и наград,
поисковые тексты заданий, а через интерфейсы Standard Expansion — имена,
registry ID и ore dictionary предметов. Произвольные поля NBT и GUI-текст сторонних
расширений автоматически не индексируются; их можно читать в деталях.
Без `query` можно просматривать все квесты.

`state`: `all` (по умолчанию), `locked`, `unlocked`, `unclaimed`, `completed`,
`repeatable`, `complete` или `incomplete`. Первые пять состояний соответствуют
BetterQuesting; последние два проверяют факт завершения независимо от награды.
`visibility`: `all` (по умолчанию), `visible` или `hidden`. Неизвестная видимость
обозначается `null` и не попадает в фильтры `visible`/`hidden`.
Просмотр включает скрытые квесты, уже загруженные в клиентскую базу.

## Навигация и полнота данных

Обычный маршрут: `bq_status` → `bq_list_lines` → `bq_get_line` → `bq_get_quest`
→ `bq_get_task` / `bq_get_reward`. Альтернатива — сразу `bq_search_quests`.
Например, найти доступные квесты про пар:

```json
{"session":"<из bq_status>","dimension":0,"query":"steam","state":"unlocked","limit":16}
```

Чтобы понять условия открытия, вызвать `bq_get_relations` с `direction: "prerequisites"`.
Чтобы узнать, что откроется дальше, использовать `dependents`. Для всей цепочки повторять
вызов с полученными UUID, сохраняя множество посещённых квестов: граф может содержать циклы.
`missing: true` означает отсутствующую ссылку, а не выполненный квест.
Учитывать `dependentQuestLogic` / `questLogic`: при OR, NOT и других правилах
нельзя считать все незавершённые предпосылки обязательными блокерами.

Списки принимают `offset` и `limit` (1–64, по умолчанию 32).
Следовать `nextOffset` **даже при пустом результате**, сохраняя фильтры.
Поиск и обратные связи сканируют до 128 кандидатов за вызов; `totalCandidates`
не является числом совпадений. В `bq_get_quest` главы, задания и награды имеют
собственные `nextOffset` в соответствующих объектах. Продолжение передаётся общим `offset`.
Длинные описания читаются по 8192 символа через `textOffset` / `nextTextOffset`;
сохраняется исходная разметка, рядом возвращается `descriptionPlain` без цветовых кодов Minecraft.

В `bq_get_quest`, `bq_get_task`, `bq_get_reward` поле `nbt` содержит ограниченное
представление родных данных BetterQuesting. Корень содержит `config`, а для квестов
и заданий — ещё `progress`, сериализованный только для текущего questing UUID.
Таким образом доступны количества, жидкости, NBT предметов, условия сравнения,
локации, сущности, выбор наград и специфические свойства расширений без угадывания их смысла.

Для вложенного поля передать `path` как JSON Pointer, например `/config/requiredItems/0`
или `/progress`. Символы `/` и `~` в ключах экранируются как `~1` и `~0`.
`nbt.omittedPaths` перечисляет усечённые ветви: повторить запрос с нужным `path`.
На выбранном уровне доступны `offset`, `limit`, `nbt.total`, `nbt.nextOffset`.
Вложенные списки/объекты ограничены 32 элементами, глубина — 6, бюджет — 4096 узлов
и 131072 символа текста. Выбранная строка читается кусками по 4096 символов через `offset`.
`nbtType` — исходный тип выбранного NBT; long возвращается десятичной строкой для точности,
NBT byte-флаги остаются числами. `null` вместе с `omittedPaths` означает усечение.

При наличии стандартных интерфейсов `items` даёт удобную таблицу `registryName`,
`displayName`, `count`, `damage`, `oreDictionary`, `hasNbt`. `count` сохраняет большие
количества BetterQuesting. Подробный NBT остаётся в `nbt`; `items` имеет свою пагинацию.
Эти записи не являются непрозрачными `itemId` NEI: для рецепта нужно отдельно найти
предмет через `nei_search_items` или инструменты GregTech.
У стандартной награды выбора также возвращается `selectedChoiceIndex` текущего игрока;
`null` означает, что вариант ещё не выбран. Чтение не изменяет выбор.

## Прогресс и ограничения

`ready` означает активного игрока и непустую локальную базу. Это **не** подтверждение
окончания синхронизации: BetterQuesting не предоставляет здесь надёжного признака
полноты или времени последнего обновления прогресса. `observedAtEpochMs` — время чтения.
Состояние квеста вычисляет сам BetterQuesting; правила группы, глобальных квестов
и повторения не заменяются упрощённым подсчётом. Наличие награды и её фактическая
доступность для выдачи — разные вещи; `canClaim` у расширений не вызывается.

Ответы содержат `revision`; его можно передать следующему вызову, чтобы при обновлении
базы получить ошибку вместо смешивания страниц. Ревизия меняется также при обновлении
прогресса, не только структуры. Без этого аргумента страницы отражают живое состояние.
Это не транзакционный снимок: сторонние моды могут менять данные без события BetterQuesting.

Чтение выполняется на END клиентского тика; сетевой ввод-вывод — в рабочих потоках.
Лимиты ограничивают объём работы адаптера, но отдельный медленный метод стороннего мода
всё равно может задержать тик. Ошибки отдельных квестов при поиске возвращаются в `errors`.
Никакие инструменты не вызывают detect, submit, claim, редактирование или открытие GUI.
Команды, ссылки и инструкции из текстов квестов/наград остаются недоверенными данными.

## Карточка квеста в Harness

Необязательный виджет находится в `integrations/harness/betterquesting`
(Gradle-проект `:harness-betterquesting-1.7.10`). Он поставляется отдельным JAR,
основному адаптеру Harness не нужен. Оба виджета проекта собираются командой:

```powershell
.\gradlew.bat build "-PharnessApiJar=C:/path/to/minecraft-harness-dev.jar"
```

Установить `build/bundle/harness-mods/minecraft-agent-tools-betterquesting-harness-1.7.10-*.jar`
в клиентский `mods/` вместе с Harness, BetterQuesting и адаптером BetterQuesting.
Gradle показывает модуль и без параметра, но Java/Forge-задачи включаются только с API JAR.

Расширение регистрирует `minecraftagenttools:quest-v1` и инструкции для агента в Harness.
После поиска квеста агент вставляет карточку рядом с пояснением:

````text
```minecraftagenttools:quest-v1
{"session":"<из bq_status>","dimension":0,"questId":"<UUID квеста>"}
```
````

JSON принимает ровно эти три поля. Название, описание, состояние и прогресс
читаются из текущей клиентской базы; текст агента не задаёт значения прогресса.
Карточка открывается на `Tasks`: первыми идут незавершённые задания, затем завершённые и необязательные.
В заголовке — та же иконка, что в книге (`NativeProps.ICON`, `OreDictTexture`),
с исходным NBT и сменой вариантов OreDictionary, состояние квеста и счётчики заданий,
предпосылок и наград. Вкладки `Tasks`, `Info`, `Loot`, `Before`, `After` показывают условия,
описание, награды, предпосылки и зависимые квесты. Есть постраничное чтение,
переход `Go` к связанному квесту и `Home` к исходному.
В каждом задании сразу видны действие, первый ресурс, текущий прогресс, требуемое
количество и остаток. Большая стрелка открывает все условия задания: до четырёх на
странице, с переходом вперёд/назад и возвратом в список. Все названия, количества и
правила сопоставления доступны при наведении; длинный текст переносится в tooltip.
Поддержаны стандартные предметные задания, крафт, жидкости (мБ), убийства, опыт,
локации, разрушение блоков, взаимодействия, встречи, scoreboard и ручная отметка.
Отдельно обозначены расход ресурсов, допустимые способы крафта, NBT/OreDictionary,
выбор одного условия и необязательные задания. Скрытые координаты не раскрываются.
У нестандартных заданий неизвестные правила и числовой прогресс не выдумываются:
карточка направляет в книгу. На странице списка до четырёх компонентов; в превью награды
до трёх предметов, награды выбора помечены отдельно.
Описание в карточке ограничено 8192 символами с явной подсказкой для длинных текстов.
Шкалы относятся к конкретным количественным условиям. Счётчик завершённых заданий
не превращается в процент завершения квеста: отображаются AND/OR/NAND/NOR/XOR/XNOR,
необходимость одновременного выполнения, доступность прогресса в заблокированном состоянии
и повторяемость. Состояние самого квеста берётся из BetterQuesting.

`Book` / `Quest book` открывает страницу выбранного квеста в стандартной книге BetterQuesting
только после нажатия пользователя. Карточка сама не вызывает detect, submit, claim
или редактирование. После открытия книги её обычные кнопки остаются под управлением игрока.
Мир, измерение и questing UUID проверяются при чтении и повторно перед переходом;
старые карточки не перепривязываются автоматически. После смены сессии нужна новая карточка.
Рисование не обращается к TCP и не сериализует весь NBT квеста.
Страницы кэшируются до 250 мс (максимум 64 страницы); события обновления BetterQuesting
сбрасывают кэш. Проверка сессии и существования квеста выполняется перед каждым чтением кэша.

## Проверка пользователем в GTNH

Сборка и изолированные тесты не запускают игру. Для проверки в целевой сборке:

1. Сверить главы и порядок с книгой, найти квест по названию и предмету.
2. Сверить описание, задания, жидкости/количества, награды выбора и пользовательский прогресс.
3. Проверить AND/OR, скрытые, повторяемые и групповые квесты; обновление после обычного выполнения игроком.
4. Пройти несколько страниц поиска и цепочку зависимостей в обе стороны.
5. Сменить измерение и мир; старый `session` должен отклоняться.
6. Удалить JAR провайдера из выбранного `plugins/`, перезапустить MCP и проверить исчезновение `bq_*`.
7. С установленным виджетом проверить карточку, все вкладки, страницы, `Go`/`Home` и
   раскрытие всех условий, точные количества, NBT-иконку и открытие выбранного квеста через
   `Book` / `Quest book`; после смены мира старые кнопки должны отклоняться.

Записать версию BetterQuesting, GTNH, commit проекта и результаты в [журнал проверки](startup-check.md).
