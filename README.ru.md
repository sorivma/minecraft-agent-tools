Самостоятельный **MCP-сервер и адаптеры Forge 1.7.10**, через которые агент получает
структурированное состояние игры. Пять отключаемых провайдеров подключают ванильный
Minecraft, NotEnoughItems, GregTech, Schematica и BetterQuesting к клиенту, поддерживающему
реализованный здесь профиль MCP HTTP. Сервер работает внутри JVM Minecraft;
внешний stdio launcher остаётся необязательным вариантом установки.

**Экспериментальный проект с реализованными инструментами и изолированными тестами.**
Проверка в игре пока частичная: зафиксированы запуск клиента GTNH и ответ
`schematic_status`, но это не подтверждает все игровые сценарии.
Подробнее — в [журнале проверки](docs/startup-check.md).
Обложка выше — иллюстрация идеи, не скриншот игры.

## Что можно спросить у агента

| Запрос | Что дают инструменты |
| --- | --- |
| «Что вокруг моей базы и что лежит в том сундуке?» | Состояние игрока, рельеф, сущности, инвентари и осмотр блоков. |
| «Где выпавший предмет?» | Поиск сущности и временная метка частицами, видимая выбранному игроку. |
| «Как это сделать и где это используется?» | Поиск предметов, рецептов и применений через обработчики установленного NEI. |
| «Что нужно для этого рецепта GregTech?» | Предметы, жидкости, EU/t, время и сведения о машинах из реестров сборки. |
| «Какой квест делать дальше и что для него нужно?» | Главы, поиск, зависимости, задания, награды и синхронизированный прогресс BetterQuesting. [Руководство](docs/betterquesting.md). |
| «Разметь мастерскую с местом под расширение». | Именованные призрачные планы Schematica, ведомость материалов и экспорт в `.schematic` / JSON. |

Это примеры запросов, а не записи демонстраций. Агент сам выбирает инструменты;
ему нужны соответствующий адаптер, токен и активная игровая сессия.
**Двигается, крафтит и ставит реальные блоки сам игрок.** Метки и схемы помогают
ориентироваться; автоматическое движение и строительство не реализованы.

## Пять интеграций — одна точка подключения

| Провайдер | Инструментов | Куда установить адаптер | Первый вызов |
| --- | ---: | --- | --- |
| **Minecraft** | 18 | Сервер Forge | `list_sessions` |
| **NEI** | 5 | Клиент с NEI GTNH | `nei_status` |
| **GregTech** | 12 | Сервер / интегрированный сервер с GTNH GregTech | `gt_status` |
| **Schematica** | 7 | Клиент со Schematica GTNH | `schematic_status` |
| **BetterQuesting** | 8 | Клиент с BetterQuesting GTNH | `bq_status` |

Каждый провайдер — отдельный JAR. Удали его из `config/minecraftagenttools/plugins/` и перезапусти Minecraft,
чтобы убрать его инструменты. Пустой каталог плагинов допустим. В ядро не встроены
Minecraft-инструменты; Minecraft Harness ему не нужен. Отдельно подключаемые
расширения Harness из `integrations/harness/` добавляют карточки схем и квестов в игровой чат.

## Как это устроено

<p align="center">
  <img src="docs/assets/architecture.svg" alt="MCP-клиент → HTTP → MCP-host и провайдеры Java 8 внутри Minecraft → очередь адаптера → игровой поток" width="100%">
</p>

Minecraft владеет MCP-сервером и его жизненным циклом:

- **Встроенный runtime Java 8.** MCP-host работает внутри Forge с Gson Minecraft.
  Codex подключается по HTTP и не запускает MCP-процесс. Закрытие или аварийное
  завершение Minecraft удаляет endpoint. Внешний stdio launcher работает на Java 21.
- **Явное разделение потоков.** Сетевые потоки обслуживают транспорт. Игровые запросы
  исполняются на нужном тике, с ограниченной очередью и сроком ожидания.
- **Привязка к миру.** Проверки сессии и измерения отклоняют устаревшие запросы после
  перехода. У каждой интеграции собственные сессии.
- **Явные границы данных.** Незагруженные чанки остаются неизвестными. Усечение
  результатов и недоступность полей модов обозначаются в ответе.

[Архитектура (EN)](docs/architecture.md) описывает границы модулей, принятые решения
и интерфейс для новых провайдеров.

## Быстрый старт

**Готовая сборка:** скачай `minecraft-agent-tools-<версия>-bundle.zip` из
[Releases](https://github.com/sorivma/minecraft-agent-tools/releases/latest), проверь
контрольную сумму по `SHA256SUMS` и распакуй архив. Затем переходи к шагу 2 ниже.
Для Forge-модов достаточно Java 8; JDK 21 нужен для сборки исходников и внешнего
stdio launcher. Файлы API, `-dev` и `-sources` предназначены разработчикам;
их не нужно устанавливать в `mods/`.

**Сборка из исходников:**

Нужны **JDK 21** для Gradle и Forge 1.7.10 для игры.
Адаптеры собираются Java 8 toolchain. Первая сборка скачивает зависимости
и инструменты старого Forge, поэтому ей нужен доступ в интернет.

```sh
git clone https://github.com/sorivma/minecraft-agent-tools.git
cd minecraft-agent-tools
./gradlew build :mcp-server:installDist
```

В Windows PowerShell: `.\gradlew.bat build :mcp-server:installDist`.
Перед сборкой укажи **JDK 21** в `JAVA_HOME`. Соседние проекты не нужны.

1. Готовый набор появится в `build/bundle/`.
2. Положи MCP-host и адаптер Minecraft из `forge/` в `mods/`.
   Нужные провайдеры скопируй в `config/minecraftagenttools/plugins/`.
3. Запусти Minecraft самостоятельно. Прочитай `http.token` из `config/minecraftagenttoolsmcp.cfg`.
4. Подключи клиент к `http://127.0.0.1:25581/mcp` с этим Bearer-токеном.
   См. [настройку встроенного MCP](docs/embedded-mcp.md).
5. Переподключи MCP-клиент. Попроси агента вызвать `list_sessions`, а затем
   `observe` с полученными сессией, измерением и UUID игрока.

MCP должен работать на том же компьютере, что и его адаптер: мост слушает только
loopback. Токен даёт административный доступ к наблюдениям — держи его в секрете.

**[Полная инструкция →](docs/getting-started.md)** — пример конфигурации, состав
набора, необязательные интеграции и решение типичных проблем.
На русском доступно [подробное руководство](docs/reference.ru.md#подключение).

## Возможности и границы проверки

| Реализовано | Ограничения |
| --- | --- |
| Инициализация MCP, список и вызов инструментов через HTTP или stdio | Поддерживается определённый профиль, не все возможности MCP. |
| Наблюдения, рецепты, временные метки и призрачные планы | Полная проверка на живых серверах и модпаках ещё не завершена. |
| Сессии, ограниченные сканирования и пагинация | Страницы снимаются отдельно и не составляют атомарный снимок мира. |
| Чтение GregTech и StructureLib | Нет универсального планировщика мультиблоков и симуляции всех аддонов. |
| Создание, сохранение и экспорт планов Schematica | Отрисовку модовых блоков и восстановление нужно проверять в игре. |

`build` запускает изолированные тесты, проверку форматирования и **готовых JAR**:
версию байткода, регистрацию провайдеров и отсутствие запрещённых включений.
Workflow GitHub выполняет эту сборку в Linux и Windows. Эти проверки не запускают
игру и не заменяют проверку игровых сценариев.

## Репозитории проекта

| Проект | Назначение |
| --- | --- |
| **Minecraft Agent Tools** | Локальный MCP, наблюдения за миром и интеграции с модами |
| [Minecraft Harness](https://github.com/sorivma/minecraft-harness) | Диалоги с агентом и интерактивные карточки в Minecraft |
| [Mira](https://github.com/sorivma/mira) | Доски, задачи и командные процессы внутри игры |

Репозитории собираются независимо. Интеграции используют явно указанные API из
релизов. [Политика версионирования](VERSIONING.md) и [история изменений](CHANGELOG.md)
описывают совместимость. CI отдельно проверяет оба расширения Harness; релизы
публикуются с контрольными суммами и подтверждением происхождения сборки.
