# Виджеты Minecraft Harness

Необязательные клиентские интеграции находятся отдельно от MCP-провайдеров (`tools/`)
и игровых адаптеров (`adapters/`). Каждая интеграция — собственный Gradle-модуль и JAR:

| Каталог | Gradle-проект | Назначение |
| --- | --- | --- |
| `schematica/` | `:harness-schematica-1.7.10` | Карточка схемы: превью, материалы, показ/скрытие и восстановление. |
| `betterquesting/` | `:harness-betterquesting-1.7.10` | Карточка квеста: описание, состояние, задания, награды, зависимости и переход в книгу. |

Оба проекта всегда отображаются в `gradlew projects` и при импорте Gradle.
Без `harnessApiJar` это проекты с базовыми задачами; их `build` сообщает, что JAR
виджета не собран. Основная сборка при этом не требует Harness.
Java/Forge-задачи интеграций включаются при явно заданном dev JAR Harness:

```powershell
.\gradlew.bat build "-PharnessApiJar=C:/path/to/minecraft-harness-dev.jar"
```

Для постоянного включения при импорте IDE можно задать `harnessApiJar` в личном
`~/.gradle/gradle.properties`, затем перезагрузить Gradle-проект. Локальный абсолютный
путь не следует добавлять в репозиторий. Проект не ищет и не собирает соседний Harness.

Результат находится в `build/bundle/harness-mods/`. Нужный JAR устанавливается
в клиентский `mods/` вместе с Harness и соответствующим игровым адаптером.
Исходный dev JAR Harness используется как `compileOnly` и не упаковывается в расширения.
Сборка без параметра очищает `harness-mods/` из bundle, даже если ранее собирались виджеты.

Виджеты регистрируются через общий API Harness. JSON карточки содержит только данные;
кнопки вызывают заранее определённые Java callbacks. Действия проверяют мир/сессию
и измерение при нажатии. Парсинг и рисование не исполняют команды и не изменяют мир.

Подробности: [Schematica](../../docs/schematica.md),
[BetterQuesting](../../docs/betterquesting.md).
